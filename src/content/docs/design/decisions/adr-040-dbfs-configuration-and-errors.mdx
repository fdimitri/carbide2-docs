## Context

v1's flusher reads `ProjectSetting` from the database *and* falls back to
environment variables (`CARBIDE_FLUSH_INTERVAL`, `CARBIDE_FLUSH_BYTES`), so
effective configuration is spread across a row, the process environment, and code
constants. Errors are mostly untyped: a stale base is handled by the agent tools
as a string result, an off-first-parent base raises a bare `RuntimeError`, and an
over-limit payload has no typed failure at all.

## Decision

**Configuration is a value object passed on instantiation; `dbfs_v2` reads no
environment variables and no database. Failures are typed. Ownership is a user
id.**

- **`Settings` is passed in, with no defaults.** A field is nil unless set, and
  nil means unset: `max_blob_bytes: nil` is no limit; nil keyframe thresholds
  mean no automatic keyframes. The caller reads wherever it likes (the project's
  row, in the application's own database) and hands a `Settings` in. This
  replaces the ENV constants, which are removed.
- **Typed errors**: `ConflictError` (a stale or off-parent base, an overlapping
  write, a target/source that advanced under a merge), `TooLargeError` (a size
  overrun — not a conflict), `RecordNotFound` for a foreign revision id.
- **A base reachable only off the first-parent line is a `ConflictError`, not a
  `RuntimeError`**, with a distinct message for "reachable only via a merge" vs
  "not a revision of this file", so callers can re-sync instead of treating it as
  a bug.
- **Refuse vs rebase is a policy**, not a hard-coded choice: an off-parent base
  either refuses (`ConflictError`) or rebases via the same diff mechanism the
  live path uses for a concurrent change. Overlapping writes still raise.
- **Regexp timeout** is applied as Ruby's process-global `Regexp.timeout` — which
  is what Ruby exposes, with the caveat that it is global and per *match*, not
  per operation.
- **Ownership is a string user id.** The forward intent is the CARB/IDE user's
  UUID, not a username and not `ENV['USER']`; passing it in is a caller-side
  change, and the `ENV['USER']` default is dropped.

## Consequences

**Positive**

- Effective configuration is one object, not a row + env + constants.
- Callers can branch on failure kind instead of parsing strings.
- The library is testable and embeddable without an environment.

**Negative / to resolve**

- `Regexp.timeout` is process-global: two Stores with different settings,
  last init wins.
- Dropping the ENV fallbacks is a behaviour change for anyone relying on them;
  the settings row becomes the only source.
- File ownership as a UUID is a forward note, not yet wired.

### The value object

```ruby
DbfsV2::Settings.new(
  max_blob_bytes:     nil,   # nil => no limit
  keyframe_revisions: nil,   # nil => no automatic keyframes
  keyframe_bytes:     nil,   # nil => no automatic keyframes
  regexp_timeout:     nil,
  off_parent_base:    :refuse # :refuse (default) | :rebase
)
DbfsV2::Store.new(project_id, settings: settings_or_nil)
```

**No defaults, and nil means unset** — not "nil means the default." A field that
silently acquires a value hides a caller mistake; nil is an honest "unset." This
replaces the `ENV.fetch('DBFS_V2_KEYFRAME_*')` constants, which are deleted.
`Store.new(project_id)` with no settings is valid and means "nothing configured."

### Errors are typed, and each one means one thing

| error | raised when | caller's response |
|---|---|---|
| `DbfsV2::ConflictError` | a stale base overlapping a write; an off-first-parent base under `:refuse`; a merge target/source that advanced under the lock | re-sync, re-read, or ask a human |
| `DbfsV2::TooLargeError` | a payload over `max_blob_bytes` | refuse; a size overrun is not a conflict |
| `ActiveRecord::RecordNotFound` | a revision id scoped to another file (BlobIO, `Content.at`) | a caller bug, not a conflict |

Two message strings on `ConflictError` are distinct on purpose: *"reachable only
off the first-parent line"* (a real state — the base exists, via a merge's second
parent) versus *"is not a revision of `<path>`"* (not a revision of this file at
all). Before this, the first case was a bare `RuntimeError` string, which reads
like a bug and which no caller handled.

### Enforced at every byte entry point

`max_blob_bytes` is checked **before** storing, at each path bytes can enter:

- `Store#write_blob_on` — the bytes-in-hand path (also `create_file(binary:)`);
- `Store#commit_blob` — the commit-by-digest path;
- `Ingest#copy_hash` — aborts the streaming copy the moment the limit is crossed,
  so an over-limit payload is never fully staged and leaves no staging file.

`BlobIO` routes through the Store, so it inherits the cap for free.

### Policy, not a constant

`off_parent_base` makes "refuse vs rebase" a project choice. `:refuse` raises
(the typed floor); `:rebase` rebases the edit onto the head via
`diff(content(base), content(head))` — the *same* mechanism the live path already
uses for a concurrent change. Overlapping writes still raise either way; the
policy governs only the off-parent case.

### The regexp timeout is global, and that is a real caveat

`regexp_timeout` is applied as Ruby's process-global `Regexp.timeout` at
`Store.new` — that is what Ruby exposes. It bounds a catastrophic-backtracking
pcre match so it raises instead of hanging. The costs are stated, not hidden: two
`Store`s with different settings means last-init wins, and the timeout is per
*match*, not per operation.

## Open questions

1. **Relaxing the ENV ban.** `Store#default_owner` still reads `ENV['USER']` as
   the file-ownership default. It is process identity rather than configuration,
   and owner is `NOT NULL`, so removing it is a behaviour change.
2. **Ownership as a user id.** The forward intent is the CARB/IDE2 user's **UUID**
   passed in by the caller — the column is a string, so it is a caller-side change
   plus dropping the `ENV['USER']` fallback. Deferred until there is a real user
   to attribute to.
3. **A size-cap default.** `max_blob_bytes: nil` means no limit, which is exactly
   what the prototype shipped. A spliced-in deployment almost certainly wants a
   number; where it is read from (the project row) is the caller's business.
## Alternatives considered

- **Keep ENV fallbacks.** Rejected: three spellings of one knob, and the library
  should not read process state.
- **Defaults in the library.** Rejected: an unset field silently acquiring a
  value hides a caller mistake; nil is an honest "unset."
- **A single `DbfsError` with a message.** Rejected: callers need to distinguish
  "re-sync" from "too large" without matching prose.
